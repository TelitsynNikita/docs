## 3.0 Пролог: парсер, который не мог закрыть скобки

Ты пишешь калькулятор, который принимает арифметическое выражение строкой и вычисляет результат. Выражение может содержать скобки:

```
"((1 + 2) * (3 + 4))"
```

Алгоритм прост: идёшь по строке, встречаешь открывающую скобку `(` — кладёшь в стек. Встречаешь закрывающую `)` — достаёшь из стека. Если в конце стек пуст — скобки сбалансированы. Если остались открывающие — не хватает закрывающих. Если встретил закрывающую, а стек пуст — не хватает открывающих.

Ты реализуешь это через `[]rune`:

```go
func isValid(s string) bool {
    stack := []rune{}
    
    for _, ch := range s {
        if ch == '(' {
            stack = append(stack, ch) // push
        } else if ch == ')' {
            if len(stack) == 0 {
                return false // закрывающая, а стек пуст
            }
            stack = stack[:len(stack)-1] // pop
        }
    }
    
    return len(stack) == 0
}
```

Тестируешь — работает. Но потом приходит задача: нужно поддерживать **три типа скобок**: круглые `()`, квадратные `[]`, фигурные `{}`. И скобки должны закрываться в правильном порядке:

- `"([{}])"` — валидно.
- `"([)]"` — невалидно, потому что `[` закрывается до `(`.

Ты модифицируешь алгоритм: при встрече закрывающей нужно проверить, что на вершине стека — **соответствующая** открывающая:

```go
func isValid(s string) bool {
    stack := []rune{}
    pairs := map[rune]rune{
        ')': '(',
        ']': '[',
        '}': '{',
    }
    
    for _, ch := range s {
        if open, ok := pairs[ch]; ok {
            // Это закрывающая скобка
            if len(stack) == 0 || stack[len(stack)-1] != open {
                return false
            }
            stack = stack[:len(stack)-1] // pop
        } else {
            // Это открывающая скобка
            stack = append(stack, ch) // push
        }
    }
    
    return len(stack) == 0
}
```

Эта задача — классика LeetCode (Valid Parentheses). И она идеально показывает, что такое **стек**: структура, где последний добавленный элемент извлекается первым (LIFO — Last In, First Out).

Но стек — это не только скобки. Это фундаментальная структура, которая лежит в основе:

- **Вызовов функций** — call stack в любом языке программирования.
- **Undo/Redo** — история действий в редакторе.
- **Парсинга** — проверка синтаксиса, вычисление выражений.
- **Обхода графов** — DFS (depth-first search).

В этой главе мы разберём три линейные структуры — **стек**, **очередь** и **дек** — и увидим, как они строятся поверх массивов и списков из Главы 2.

## 3.1 Стек: LIFO

### 🔌 Проблема: как хранить данные, чтобы последний добавленный был первым?

В прологе мы столкнулись со стеком через задачу про скобки. Но давай поймём стек **системно**.

**Стек (stack)** — это структура данных, которая хранит элементы в порядке добавления и позволяет извлекать их **в обратном порядке**: последний добавленный — первый извлечённый.

Принцип **LIFO** — Last In, First Out («последним пришёл — первым ушёл»).

### 📊 Аналогия: стопка тарелок

Представь стопку тарелок в столовой. Ты кладёшь тарелки **наверх**. Когда нужна тарелка, ты берёшь **сверху**. Тарелка, которую положили последней, будет взята первой. Тарелка на самом дне пролежит дольше всех.

Стек работает точно так же:

- **Push** (положить) — добавить элемент на вершину.
- **Pop** (взять) — извлечь элемент с вершины.
- **Peek** (посмотреть) — посмотреть на вершину, не извлекая.

### 📐 Операции стека

| Операция | Что делает | Сложность |
|:---|:---|:---|
| `push(x)` | Добавляет x на вершину | O(1) |
| `pop()` | Извлекает и возвращает вершину | O(1) |
| `peek()` | Возвращает вершину, не извлекая | O(1) |
| `isEmpty()` | Проверяет, пуст ли стек | O(1) |
| `size()` | Возвращает количество элементов | O(1) |

Все операции — O(1), потому что мы работаем только с **одним концом** структуры. Никаких сдвигов, никаких поисков.

### 🔬 Реализация на slice

Стек проще всего реализовать на slice: вершина — последний элемент слайса.

```go
type Stack struct {
    items []int
}

func NewStack() *Stack {
    return &Stack{items: []int{}}
}

func (s *Stack) Push(x int) {
    s.items = append(s.items, x) // O(1) амортизированно
}

func (s *Stack) Pop() (int, bool) {
    if len(s.items) == 0 {
        return 0, false // стек пуст
    }
    x := s.items[len(s.items)-1]
    s.items = s.items[:len(s.items)-1]
    return x, true
}

func (s *Stack) Peek() (int, bool) {
    if len(s.items) == 0 {
        return 0, false
    }
    return s.items[len(s.items)-1], true
}

func (s *Stack) IsEmpty() bool {
    return len(s.items) == 0
}

func (s *Stack) Size() int {
    return len(s.items)
}
```

**Почему slice:** потому что `append` — амортизированное O(1), а удаление с конца — O(1). Идеально для стека.

### 🔬 Реализация на связном списке

Стек можно реализовать и на связном списке: вершина — голова списка.

```go
type Node struct {
    Value int
    Next  *Node
}

type Stack struct {
    head *Node
    size int
}

func (s *Stack) Push(x int) {
    s.head = &Node{Value: x, Next: s.head} // вставка в начало — O(1)
    s.size++
}

func (s *Stack) Pop() (int, bool) {
    if s.head == nil {
        return 0, false
    }
    x := s.head.Value
    s.head = s.head.Next // удаление из начала — O(1)
    s.size--
    return x, true
}
```

**Когда использовать список, а не slice:** когда нужны гарантии O(1) на **каждую** операцию (а не амортизированно) — например, в системах реального времени, где недопустима пауза на расширение слайса.

### 🧮 Зачем нужен стек: реальные применения

**1. Call Stack (стек вызовов)**

Когда программа вызывает функцию, в стек помещается **frame** — контекст вызова: аргументы, локальные переменные, адрес возврата. Когда функция завершается, frame извлекается, и программа продолжается с того места, где была вызвана.

```go
func a() {
    b() // push frame b
    // после return — pop frame b
}

func b() {
    c() // push frame c
    // после return — pop frame c
}
```

**2. Undo/Redo в редакторе**

Каждое действие пользователя — push в стек undo. Нажатие «отменить» — pop из undo и push в redo. «Вернуть» — pop из redo и push в undo.

**3. Парсинг выражений**

Обратная польская запись (RPN): `"3 4 + 5 *"` — это `(3 + 4) * 5`. Вычисляется через стек: встречаешь число — push, встречаешь оператор — pop два числа, вычисляешь, push результат.

**4. Проверка скобок**

Задача из пролога. Открывающая — push, закрывающая — pop и проверка.

**5. DFS (обход графа в глубину)**

Рекурсивный DFS использует call stack. Итеративный — явный стек. Разберём в Главе 13.

### 💡 Что мы узнали?

- Стек — структура LIFO: последний добавленный — первый извлечённый.
- Операции: push, pop, peek — все O(1).
- Реализуется на slice (вершина — конец) или на связном списке (вершина — голова).
- Применения: call stack, undo/redo, парсинг, проверка скобок, DFS.

## 3.2 Очередь: FIFO

### 🔌 Проблема: как обрабатывать задачи в порядке их поступления?

В подглаве 3.1 мы разобрали стек — структуру LIFO. Но есть задачи, где порядок **противоположный**: первый добавленный должен быть первым обработанным.

Представь: ты пишешь сервис, который принимает запросы от пользователей. Запросы приходят в произвольное время. Обрабатывать их нужно **в порядке поступления** — тот, кто пришёл раньше, должен быть обслужен раньше. Если ты будешь обрабатывать последний запрос первым (как стек), то первый пользователь будет ждать бесконечно, если запросы продолжают приходить.

Тебе нужна структура **FIFO** — First In, First Out («первым пришёл — первым ушёл»). Эта структура — **очередь (queue)**.

### 📊 Аналогия: очередь в магазине

Люди встают в очередь к кассе. Первый, кто пришёл, первым будет обслужен. Новые люди встают **в конец** очереди. Кассир берёт людей **из начала**.

Очередь работает точно так же:

- **Enqueue** (встать в очередь) — добавить элемент в конец.
- **Dequeue** (выйти из очереди) — извлечь элемент из начала.

### 📐 Операции очереди

| Операция | Что делает | Сложность |
|:---|:---|:---|
| `enqueue(x)` | Добавляет x в конец | O(1) |
| `dequeue()` | Извлекает и возвращает из начала | O(1) |
| `front()` | Возвращает первый элемент, не извлекая | O(1) |
| `isEmpty()` | Проверяет, пуста ли очередь | O(1) |
| `size()` | Возвращает количество элементов | O(1) |

Все операции — O(1), потому что мы работаем только с **двумя концами**: добавление в конец, извлечение из начала.

### 🔬 Реализация на slice (наивная — с проблемой)

Первая мысль: реализовать очередь на slice, как стек. Но тут есть подвох.

**Наивная реализация:**

```go
type Queue struct {
    items []int
}

func (q *Queue) Enqueue(x int) {
    q.items = append(q.items, x) // O(1) амортизированно
}

func (q *Queue) Dequeue() (int, bool) {
    if len(q.items) == 0 {
        return 0, false
    }
    x := q.items[0]
    q.items = q.items[1:] // ← ПРОБЛЕМА: сдвиг всех элементов — O(n)
    return x, true
}
```

**В чём проблема:** `q.items[1:]` — это срез, который **не копирует данные**, а просто сдвигает указатель. Звучит как O(1), но на самом деле:

1. `q.items[1:]` — новый slice, указывающий на `items[1]`. O(1).
2. Но старый элемент `items[0]` **остаётся в памяти** — на него всё ещё ссылается базовый массив.
3. После многих dequeue база растёт, а начало «съедается» — это **утечка памяти**.

Хуже того: если ты делаешь `q.items = append(q.items[1:], x)`, то при переполнении ёмкости append выделит новый массив и **скопирует все оставшиеся элементы** — O(n).

Поэтому на slice очередь напрямую не делают. Нужен либо **кольцевой буфер**, либо **связный список**.

### 🔬 Реализация на связном списке

Связный список идеален для очереди: добавление в конец — O(1), удаление из начала — O(1). Нужно только хранить указатели на **голову** и **хвост**.

```go
type Node struct {
    Value int
    Next  *Node
}

type Queue struct {
    head *Node // начало очереди (для dequeue)
    tail *Node // конец очереди (для enqueue)
    size int
}

func (q *Queue) Enqueue(x int) {
    newNode := &Node{Value: x}
    
    if q.tail == nil {
        // Очередь пуста — новый узел и голова, и хвост
        q.head = newNode
        q.tail = newNode
    } else {
        // Добавляем в конец
        q.tail.Next = newNode
        q.tail = newNode
    }
    
    q.size++
}

func (q *Queue) Dequeue() (int, bool) {
    if q.head == nil {
        return 0, false
    }
    
    x := q.head.Value
    q.head = q.head.Next
    
    if q.head == nil {
        // Очередь опустела — сбрасываем хвост
        q.tail = nil
    }
    
    q.size--
    return x, true
}

func (q *Queue) Front() (int, bool) {
    if q.head == nil {
        return 0, false
    }
    return q.head.Value, true
}

func (q *Queue) IsEmpty() bool {
    return q.head == nil
}

func (q *Queue) Size() int {
    return q.size
}
```

**Сложность:** enqueue — O(1), dequeue — O(1), front — O(1). Все операции — гарантированно O(1), без амортизации.

### 🔬 Реализация на кольцевом буфере

**Кольцевой буфер (ring buffer)** — это массив, который «закольцован»: когда ты доходишь до конца массива, следующий индекс — 0.

```
Массив размером 5:
[_, _, _, _, _]
 0  1  2  3  4

После enqueue(1), enqueue(2), enqueue(3):
[1, 2, 3, _, _]
 head=0, tail=3

После dequeue(), dequeue():
[_, _, 3, _, _]
 head=2, tail=3

После enqueue(4), enqueue(5), enqueue(6):
[6, _, 3, 4, 5]
    ↑  ↑  ↑  ↑
    |  |  |  tail=1 (закольцевалось!)
    |  |  head=2
    |  index=0 → 6
    index=1 → 5
```

**Ключевая идея:** индексы вычисляются по модулю размера массива. Когда tail достигает конца, он перескакивает на 0.

```go
type RingBuffer struct {
    items []int
    head  int // индекс первого элемента
    tail  int // индекс следующего свободного места
    count int // количество элементов
    cap   int
}

func NewRingBuffer(capacity int) *RingBuffer {
    return &RingBuffer{
        items: make([]int, capacity),
        cap:   capacity,
    }
}

func (rb *RingBuffer) Enqueue(x int) bool {
    if rb.count == rb.cap {
        return false // буфер полон
    }
    
    rb.items[rb.tail] = x
    rb.tail = (rb.tail + 1) % rb.cap // закольцовка
    rb.count++
    return true
}

func (rb *RingBuffer) Dequeue() (int, bool) {
    if rb.count == 0 {
        return 0, false
    }
    
    x := rb.items[rb.head]
    rb.head = (rb.head + 1) % rb.cap // закольцовка
    rb.count--
    return x, true
}
```

**Когда использовать кольцевой буфер:** когда очередь имеет **фиксированную максимальную ёмкость** и ты не хочешь выделять память динамически. Например, буфер сетевых пакетов, аудио-буфер.

**Когда использовать связный список:** когда ёмкость неизвестна и очередь может расти бесконечно.

### 🧮 Зачем нужна очередь: реальные применения

**1. Обработка задач в порядке поступления**

Веб-сервер принимает запросы. Если обработчик занят, запросы встают в очередь. Когда обработчик освобождается, он берёт следующий запрос из очереди.

**2. BFS (обход графа в ширину)**

Алгоритм обхода графа, где вершины посещаются **по уровням**. Сначала корень, потом соседи, потом соседи соседей. Очередь хранит вершины, которые нужно посетить. Разберём детально в Главе 13.

**3. Буферы в Kafka**

Сообщения в Kafka-партиции — это очередь. Продюсер пишет в конец, консюмер читает из начала. Порядок сообщений сохраняется.

**4. Планировщики задач**

Операционная система поддерживает очередь готовых процессов. Процессы, готовые к выполнению, стоят в очереди. Планировщик берёт следующий процесс из очереди.

**5. Очередь сообщений в Go**

Каналы в Go (`chan`) — это по сути очередь. Отправка в канал — enqueue, получение — dequeue. Буферизированные каналы — это кольцевые буферы.

### 📊 Стек vs очередь

| | Стек (LIFO) | Очередь (FIFO) |
|:---|:---|:---|
| Добавление | push — на вершину | enqueue — в конец |
| Извлечение | pop — с вершины | dequeue — из начала |
| Аналогия | Стопка тарелок | Очередь в магазине |
| Порядок | Последний → первый | Первый → первый |
| Применение | Undo, call stack, DFS | Буферы, BFS, планировщики |

### 💡 Что мы узнали?

- Очередь — структура FIFO: первый добавленный — первый извлечённый.
- Операции: enqueue, dequeue, front — все O(1).
- На slice очередь напрямую не делают — сдвиг O(n) или утечка памяти.
- Реализация на связном списке: head + tail, O(1) на все операции.
- Реализация на кольцевом буфере: фиксированная ёмкость, индексы по модулю.
- Применения: BFS, буферы, планировщики, каналы в Go.

## 3.3 Дек: двусторонняя очередь

### 🔌 Проблема: что если нужно добавлять и извлекать с обоих концов?

Стек позволяет добавлять и извлекать только с **одного** конца. Очередь — добавлять в **конец**, извлекать из **начала**. Но есть задачи, где нужны **оба конца** одновременно.

Представь: ты пишешь плеер. Пользователь может добавлять песни **в конец** очереди воспроизведения (как в обычной очереди), но также может вставить песню **в начало** («играть следующей»). И при этом он может убрать песню как из начала (когда она закончилась), так и из конца (если передумал).

Нужна структура, которая поддерживает:

- Добавление в начало — O(1).
- Добавление в конец — O(1).
- Извлечение из начала — O(1).
- Извлечение из конца — O(1).

Эта структура — **дек (deque)** — **Double-Ended Queue** — «двусторонняя очередь».

### 📐 Что такое дек

**Дек** — это структура данных, которая объединяет стек и очередь. Она позволяет добавлять и извлекать элементы **с обоих концов**.

Это как колода карт, с которой можно снимать и сверху, и снизу, и подкладывать с обеих сторон.

### 📊 Операции дека

| Операция | Что делает | Сложность |
|:---|:---|:---|
| `pushFront(x)` | Добавляет x в начало | O(1) |
| `pushBack(x)` | Добавляет x в конец | O(1) |
| `popFront()` | Извлекает и возвращает из начала | O(1) |
| `popBack()` | Извлекает и возвращает из конца | O(1) |
| `front()` | Возвращает первый элемент | O(1) |
| `back()` | Возвращает последний элемент | O(1) |
| `isEmpty()` | Проверяет, пуст ли дек | O(1) |
| `size()` | Возвращает количество элементов | O(1) |

### 🔬 Реализация на двусвязном списке

Дек проще всего реализовать на **двусвязном списке** — каждый узел имеет указатели на следующий и предыдущий.

```go
type Node struct {
    Value int
    Prev  *Node
    Next  *Node
}

type Deque struct {
    head *Node
    tail *Node
    size int
}

func (d *Deque) PushFront(x int) {
    newNode := &Node{Value: x}
    
    if d.head == nil {
        d.head = newNode
        d.tail = newNode
    } else {
        newNode.Next = d.head
        d.head.Prev = newNode
        d.head = newNode
    }
    
    d.size++
}

func (d *Deque) PushBack(x int) {
    newNode := &Node{Value: x}
    
    if d.tail == nil {
        d.head = newNode
        d.tail = newNode
    } else {
        newNode.Prev = d.tail
        d.tail.Next = newNode
        d.tail = newNode
    }
    
    d.size++
}

func (d *Deque) PopFront() (int, bool) {
    if d.head == nil {
        return 0, false
    }
    
    x := d.head.Value
    d.head = d.head.Next
    
    if d.head == nil {
        d.tail = nil
    } else {
        d.head.Prev = nil
    }
    
    d.size--
    return x, true
}

func (d *Deque) PopBack() (int, bool) {
    if d.tail == nil {
        return 0, false
    }
    
    x := d.tail.Value
    d.tail = d.tail.Prev
    
    if d.tail == nil {
        d.head = nil
    } else {
        d.tail.Next = nil
    }
    
    d.size--
    return x, true
}
```

### 🔬 Реализация на кольцевом буфере

Дек можно реализовать и на кольцевом буфере — как очередь, но с операциями с обоих концов.

```go
type Deque struct {
    items []int
    head  int
    tail  int
    count int
    cap   int
}

func NewDeque(capacity int) *Deque {
    return &Deque{
        items: make([]int, capacity),
        cap:   capacity,
    }
}

func (d *Deque) PushFront(x int) bool {
    if d.count == d.cap {
        return false
    }
    
    d.head = (d.head - 1 + d.cap) % d.cap // сдвиг влево с закольцовкой
    d.items[d.head] = x
    d.count++
    return true
}

func (d *Deque) PushBack(x int) bool {
    if d.count == d.cap {
        return false
    }
    
    d.items[d.tail] = x
    d.tail = (d.tail + 1) % d.cap
    d.count++
    return true
}

func (d *Deque) PopFront() (int, bool) {
    if d.count == 0 {
        return 0, false
    }
    
    x := d.items[d.head]
    d.head = (d.head + 1) % d.cap
    d.count--
    return x, true
}

func (d *Deque) PopBack() (int, bool) {
    if d.count == 0 {
        return 0, false
    }
    
    d.tail = (d.tail - 1 + d.cap) % d.cap
    x := d.items[d.tail]
    d.count--
    return x, true
}
```

### 🧮 Зачем нужен дек: реальные применения

**1. Скользящее окно**

Задача: дан массив и размер окна k. Для каждого окна найти максимум (или минимум). Дек хранит индексы элементов, которые могут быть максимумом. Разберём в подглаве 3.5.

**2. Undo/Redo с ограничением по памяти**

История действий в редакторе: новые действия добавляются в конец. Когда история заполнена, старые удаляются из начала. Это дек с фиксированной ёмкостью.

**3. Планировщик с приоритетами**

Задачи с высоким приоритетом добавляются в начало дека, с низким — в конец. Обработка — из начала.

**4. BFS с двусторонним обходом**

Некоторые алгоритмы на графах (например, 0-1 BFS) используют дек: если вес ребра 0 — добавляем в начало, если 1 — в конец.

**5. Проверка на палиндром**

Читаем строку в дек. Сравниваем первый и последний символы, удаляем их. Если все совпали — палиндром.

### 📊 Стек vs Очередь vs Дек

| Операция | Стек | Очередь | Дек |
|:---|:---|:---|:---|
| pushFront | ❌ | ❌ | ✅ O(1) |
| pushBack | ✅ O(1) | ✅ O(1) | ✅ O(1) |
| popFront | ❌ | ✅ O(1) | ✅ O(1) |
| popBack | ✅ O(1) | ❌ | ✅ O(1) |

Стек — это дек, где доступен только один конец. Очередь — это дек, где добавление только в конец, извлечение только из начала. Дек — обобщение обеих структур.

### 💡 Что мы узнали?

- Дек — двусторонняя очередь: добавление и извлечение с обоих концов за O(1).
- Реализуется на двусвязном списке или кольцевом буфере.
- Стек и очередь — частные случаи дека.
- Применения: скользящее окно, история с ограничением, BFS с весами 0/1.

## 3.4 Монотонный стек

### 🔌 Проблема: найти следующий больший элемент

Ты решаешь задачу: дан массив чисел. Для каждого элемента найди **следующий больший элемент** — первый элемент справа, который больше текущего. Если такого нет — верни -1.

**Пример:**

```
Вход:  [2, 1, 5, 6, 2, 3]
Выход: [5, 5, 6, -1, 3, -1]

Объяснение:
2 → следующий больший: 5 (первый справа, кто больше 2)
1 → следующий больший: 5
5 → следующий больший: 6
6 → следующего большего нет → -1
2 → следующий больший: 3
3 → следующего большего нет → -1
```

**Наивное решение:** для каждого элемента пройтись по всем элементам справа и найти первый больший. Сложность: O(n²).

**Вопрос:** можно ли решить за O(n)?

Ответ — **монотонный стек**.

### 📐 Что такое монотонный стек

**Монотонный стек** — это стек, который поддерживает элементы в **монотонном порядке**: либо только возрастающем, либо только убывающем.

**Ключевая идея:** при добавлении нового элемента мы **выталкиваем** из стека все элементы, которые нарушают монотонность. Вытолкнутые элементы — это те, для которых текущий элемент является **ответом**.

Звучит абстрактно. Давай на примере.

### 🔬 Решаем задачу «следующий больший элемент»

Идём по массиву слева направо. Поддерживаем стек, в котором элементы **убывают** (от большего к меньшему).

**Алгоритм:**

1. Для каждого элемента x:
   - Пока стек не пуст и `x > стек.вершина`:
     - Выталкиваем вершину `top` из стека.
     - Для `top` следующий больший — это `x`.
   - Кладём `x` в стек.

**Почему это работает:**

Когда мы встречаем элемент `x`, который больше вершины стека, это значит, что `x` — **следующий больший** для всех элементов в стеке, которые меньше `x`. Мы выталкиваем их и записываем ответ.

Элементы, которые остались в стеке после прохода, — это те, для которых следующего большего нет (или он ещё не встретился). Для них ответ — -1.

**Код на Go:**

```go
func nextGreaterElement(nums []int) []int {
    n := len(nums)
    result := make([]int, n)
    for i := range result {
        result[i] = -1 // по умолчанию — нет следующего большего
    }
    
    stack := []int{} // хранит индексы элементов
    
    for i := 0; i < n; i++ {
        // Выталкиваем элементы, для которых nums[i] — следующий больший
        for len(stack) > 0 && nums[i] > nums[stack[len(stack)-1]] {
            idx := stack[len(stack)-1]     // индекс выталкиваемого
            stack = stack[:len(stack)-1]   // pop
            result[idx] = nums[i]          // следующий больший для idx — nums[i]
        }
        stack = append(stack, i) // push текущий индекс
    }
    
    return result
}
```

**Пошагово на примере `[2, 1, 5, 6, 2, 3]`:**

```
i=0, nums[0]=2:
  Стек пуст → push 0. Стек: [0]

i=1, nums[1]=1:
  nums[1]=1 < nums[0]=2 → не выталкиваем. Push 1. Стек: [0, 1]

i=2, nums[2]=5:
  5 > nums[1]=1 → pop 1, result[1]=5. Стек: [0]
  5 > nums[0]=2 → pop 0, result[0]=5. Стек: []
  Push 2. Стек: [2]

i=3, nums[3]=6:
  6 > nums[2]=5 → pop 2, result[2]=6. Стек: []
  Push 3. Стек: [3]

i=4, nums[4]=2:
  2 < nums[3]=6 → не выталкиваем. Push 4. Стек: [3, 4]

i=5, nums[5]=3:
  3 > nums[4]=2 → pop 4, result[4]=3. Стек: [3]
  3 < nums[3]=6 → остановились. Push 5. Стек: [3, 5]

Конец. Стек: [3, 5] — для них нет следующего большего, result = -1 (по умолчанию).
```

**Результат:** `[5, 5, 6, -1, 3, -1]` — совпадает с ожиданием.

**Сложность:** O(n) по времени, хотя внутри два цикла. Почему? Потому что каждый элемент **кладётся в стек один раз** и **выталкивается один раз**. Суммарное количество операций push + pop = 2n = O(n).

### 📊 Монотонно убывающий vs монотонно возрастающий

В задаче выше мы использовали **убывающий стек** (от большего к меньшему). Это решает задачу «следующий больший».

Если нужно найти **следующий меньший**, используется **возрастающий стек** (от меньшего к большему).

| Тип стека | Порядок | Решает задачу |
|:---|:---|:---|
| Убывающий | Большой → маленький | Следующий больший элемент |
| Возрастающий | Маленький → большой | Следующий меньший элемент |

**Пример: следующий меньший элемент**

```go
func nextSmallerElement(nums []int) []int {
    n := len(nums)
    result := make([]int, n)
    for i := range result {
        result[i] = -1
    }
    
    stack := []int{} // возрастающий стек
    
    for i := 0; i < n; i++ {
        // Выталкиваем элементы, для которых nums[i] — следующий меньший
        for len(stack) > 0 && nums[i] < nums[stack[len(stack)-1]] {
            idx := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            result[idx] = nums[i]
        }
        stack = append(stack, i)
    }
    
    return result
}
```

Отличие — только в знаке сравнения: `nums[i] < nums[stack[top]]` вместо `>`.

### 🧮 Другие задачи, которые решает монотонный стек

**1. Наибольший прямоугольник в гистограмме**

Дан массив высот столбцов. Найти максимальный прямоугольник, который можно построить. Классическая задача, решается через монотонный стек за O(n).

**2. Daily Temperatures**

Дан массив температур. Для каждого дня найти, через сколько дней температура станет выше. Это та же задача «следующий больший», только для индексов.

**3. Trapping Rain Water**

Дан массив высот. Найти, сколько воды задержится после дождя. Решается через монотонный стек или два указателя.

**4. Проверка скобочной последовательности с типами**

Обобщение задачи из пролога: стек + монотонность (вложенность скобок должна быть правильной).

### 💡 Что мы узнали?

- Монотонный стек — стек, поддерживающий элементы в возрастающем или убывающем порядке.
- При добавлении нового элемента выталкиваем все, которые нарушают монотонность.
- Вытолкнутые элементы — это те, для которых текущий — ответ.
- Решает задачи «следующий больший/меньший», «наибольший прямоугольник», «daily temperatures».
- Сложность — O(n), несмотря на вложенные циклы (каждый элемент push/pop один раз).

## 3.5 Монотонная очередь

### 🔌 Проблема: максимум в скользящем окне

Ты решаешь задачу: дан массив чисел и размер окна k. Окно движется слева направо. Для каждого положения окна найди **максимум** внутри него.

**Пример:**

```
Вход: nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
Выход: [3, 3, 5, 5, 6, 7]

Объяснение:
Окно [1, 3, -1] → максимум 3
Окно [3, -1, -3] → максимум 3
Окно [-1, -3, 5] → максимум 5
Окно [-3, 5, 3] → максимум 5
Окно [5, 3, 6] → максимум 6
Окно [3, 6, 7] → максимум 7
```

**Наивное решение:** для каждого окна пройтись по k элементам и найти максимум. Сложность: O(n·k). При больших k — катастрофа.

**Вопрос:** можно ли решить за O(n)?

Ответ — **монотонная очередь**.

### 📐 Что такое монотонная очередь

**Монотонная очередь** — это дек, который поддерживает элементы в **монотонном порядке** и при этом сохраняет **порядок их добавления** (FIFO).

В отличие от монотонного стека, где элементы только добавляются и выталкиваются с одного конца, в монотонной очереди:

- **Добавление** — в конец, с выталкиванием из конца всё, что нарушает монотонность.
- **Удаление** — из начала, когда элемент выходит за пределы окна.

**Ключевая идея:** хранить в очереди **не значения**, а **индексы** элементов, которые могут быть максимумом текущего окна.

### 🔬 Решаем задачу «максимум в скользящем окне»

**Алгоритм:**

1. Идём по массиву слева направо.
2. Для каждого элемента x = nums[i]:
   - **Удаляем из начала** очереди все индексы, которые вышли за пределы окна (индекс < i - k + 1).
   - **Выталкиваем из конца** очереди все индексы, чьи значения меньше x. Они никогда не станут максимумом, потому что x больше и находится правее.
   - **Добавляем** i в конец очереди.
   - **Фронт очереди** — индекс максимума текущего окна.

**Почему очередь монотонно убывающая:**

Мы выталкиваем из конца всё, что меньше текущего x. Значит, значения в очереди идут **по убыванию** от фронта к хвосту. Фронт — максимум.

**Код на Go:**

```go
func maxSlidingWindow(nums []int, k int) []int {
    n := len(nums)
    if n == 0 {
        return []int{}
    }
    
    result := make([]int, 0, n-k+1)
    deque := []int{} // хранит индексы
    
    for i := 0; i < n; i++ {
        // 1. Удаляем из начала индексы, вышедшие за окно
        for len(deque) > 0 && deque[0] < i-k+1 {
            deque = deque[1:] // popFront
        }
        
        // 2. Выталкиваем из конца всё, что меньше nums[i]
        for len(deque) > 0 && nums[deque[len(deque)-1]] < nums[i] {
            deque = deque[:len(deque)-1] // popBack
        }
        
        // 3. Добавляем текущий индекс
        deque = append(deque, i) // pushBack
        
        // 4. Если окно сформировано — фронт это максимум
        if i >= k-1 {
            result = append(result, nums[deque[0]])
        }
    }
    
    return result
}
```

**Пошагово на примере `[1, 3, -1, -3, 5, 3, 6, 7]`, k=3:**

```
i=0, nums[0]=1:
  deque пуст → push 0. deque: [0]
  Окно не сформировано (i < k-1)

i=1, nums[1]=3:
  deque[0]=0 >= i-k+1=0 → не удаляем
  nums[deque[1-1]]=nums[0]=1 < 3 → pop 0
  push 1. deque: [1]
  Окно не сформировано

i=2, nums[2]=-1:
  deque[0]=1 >= 1 → не удаляем
  nums[deque[1-1]]=nums[1]=3 > -1 → не выталкиваем
  push 2. deque: [1, 2]
  Окно сформировано (i >= 2). Максимум: nums[deque[0]]=nums[1]=3. result=[3]

i=3, nums[3]=-3:
  deque[0]=1 >= 1 → не удаляем
  nums[deque[2-1]]=nums[2]=-1 > -3 → не выталкиваем
  push 3. deque: [1, 2, 3]
  Максимум: nums[1]=3. result=[3, 3]

i=4, nums[4]=5:
  deque[0]=1 >= 2 → не удаляем
  nums[deque[3-1]]=nums[3]=-3 < 5 → pop 3
  nums[deque[2-1]]=nums[2]=-1 < 5 → pop 2
  nums[deque[1-1]]=nums[1]=3 < 5 → pop 1
  push 4. deque: [4]
  Максимум: nums[4]=5. result=[3, 3, 5]

i=5, nums[5]=3:
  deque[0]=4 >= 3 → не удаляем
  nums[deque[1-1]]=nums[4]=5 > 3 → не выталкиваем
  push 5. deque: [4, 5]
  Максимум: nums[4]=5. result=[3, 3, 5, 5]

i=6, nums[6]=6:
  deque[0]=4 >= 4 → не удаляем
  nums[deque[2-1]]=nums[5]=3 < 6 → pop 5
  nums[deque[1-1]]=nums[4]=5 < 6 → pop 4
  push 6. deque: [6]
  Максимум: nums[6]=6. result=[3, 3, 5, 5, 6]

i=7, nums[7]=7:
  deque[0]=6 >= 5 → не удаляем
  nums[deque[1-1]]=nums[6]=6 < 7 → pop 6
  push 7. deque: [7]
  Максимум: nums[7]=7. result=[3, 3, 5, 5, 6, 7]
```

**Результат:** `[3, 3, 5, 5, 6, 7]` — совпадает.

**Сложность:** O(n) по времени. Каждый индекс добавляется и удаляется ровно один раз.

### 📊 Монотонный стек vs монотонная очередь

| | Монотонный стек | Монотонная очередь |
|:---|:---|:---|
| Структура | Стек (LIFO) | Дек (FIFO с обоих концов) |
| Добавление | Только в конец (push) | В конец (pushBack) |
| Удаление | Из конца (pop) | Из начала (popFront) и конца (popBack) |
| Задача | Следующий больший/меньший | Максимум/минимум в окне |
| Ограничение окна | Нет | Есть — элементы выходят по FIFO |

### 🧮 Другие задачи, которые решает монотонная очередь

**1. Минимум в скользящем окне**

Та же задача, но ищем минимум. Отличие — знак сравнения: выталкиваем всё, что **больше** текущего.

**2. Ограничение на разницу**

Найти подмассив, где разница между максимумом и минимумом не превышает заданное значение. Два монотонных дека: один для максимума, другой для минимума.

**3. Максимум подмассива с ограничением длины**

Найти подмассив фиксированной длины с максимальной суммой. Монотонная очередь хранит префиксные суммы.

### 💡 Что мы узнали?

- Монотонная очередь — дек, поддерживающий монотонный порядок + FIFO.
- Добавление: в конец, выталкивая всё, что нарушает монотонность.
- Удаление: из начала, когда элемент выходит за пределы окна.
- Решает задачу «максимум/минимум в скользящем окне» за O(n).
- Фронт очереди — всегда максимум (или минимум) текущего окна.
- Каждый элемент добавляется и удаляется ровно один раз.

### 📝 Задача 1: Обратная польская запись (Evaluate Reverse Polish Notation)

**Формулировка:** дано выражение в обратной польской записи (RPN). Вычисли его.

**Пример:**

```
Вход: ["2", "1", "+", "3", "*"]
Выход: 9
Объяснение: (2 + 1) * 3 = 9
```

**Подход:**

Идём по токенам. Если число — push в стек. Если оператор — pop два числа, вычисляем, push результат.

**Код:**

```go
func evalRPN(tokens []string) int {
    stack := []int{}
    
    for _, token := range tokens {
        switch token {
        case "+", "-", "*", "/":
            b := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            a := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            
            var result int
            switch token {
            case "+":
                result = a + b
            case "-":
                result = a - b
            case "*":
                result = a * b
            case "/":
                result = a / b
            }
            
            stack = append(stack, result)
        default:
            num, _ := strconv.Atoi(token)
            stack = append(stack, num)
        }
    }
    
    return stack[0]
}
```

**Сложность:** O(n) по времени, O(n) по памяти (стек).

### 📝 Задача 2: Очередь через два стека (Implement Queue using Stacks)

**Формулировка:** реализуй очередь, используя только два стека.

**Подход:**

Два стека: `in` (для enqueue) и `out` (для dequeue).

- **enqueue(x):** push в `in`.
- **dequeue():** если `out` пуст — перекладываем все из `in` в `out` (порядок разворачивается). Потом pop из `out`.

**Код:**

```go
type MyQueue struct {
    in  []int
    out []int
}

func (q *MyQueue) Enqueue(x int) {
    q.in = append(q.in, x)
}

func (q *MyQueue) Dequeue() int {
    if len(q.out) == 0 {
        // Перекладываем in → out (разворачиваем порядок)
        for len(q.in) > 0 {
            x := q.in[len(q.in)-1]
            q.in = q.in[:len(q.in)-1]
            q.out = append(q.out, x)
        }
    }
    
    x := q.out[len(q.out)-1]
    q.out = q.out[:len(q.out)-1]
    return x
}
```

**Сложность:** enqueue — O(1). Dequeue — амортизированное O(1): каждый элемент перекладывается не более одного раза.

## 3.7 Итог: что мы узнали о стеке, очереди и деке

Мы начали с задачи про скобки и пришли к пяти структурам:

1. **Стек** — LIFO. Push, pop, peek — O(1).
2. **Очередь** — FIFO. Enqueue, dequeue — O(1).
3. **Дек** — двусторонняя очередь. Все операции — O(1).
4. **Монотонный стек** — стек, поддерживающий порядок. Следующий больший/меньший.
5. **Монотонная очередь** — дек с порядком. Максимум/минимум в окне.

Это фундаментальные линейные структуры, которые строятся **поверх** массивов и связных списков. Они используются в реальных системах повсюду: call stack, undo/redo, парсинг, планировщики, буферы, BFS.

---

## Глоссарий

| Термин | Определение |
|:---|:---|
| **Стек** | Структура LIFO: последний добавленный — первый извлечённый |
| **Очередь** | Структура FIFO: первый добавленный — первый извлечённый |
| **Дек** | Двусторонняя очередь: добавление/извлечение с обоих концов |
| **Push** | Добавить элемент в стек |
| **Pop** | Извлечь элемент из стека |
| **Enqueue** | Добавить элемент в очередь |
| **Dequeue** | Извлечь элемент из очереди |
| **Кольцевой буфер** | Массив, где индексы вычисляются по модулю |
| **Монотонный стек** | Стек с элементами в возрастающем/убывающем порядке |
| **Монотонная очередь** | Дек с монотонным порядком + FIFO |
| **LIFO** | Last In, First Out — последний пришёл, первый ушёл |
| **FIFO** | First In, First Out — первый пришёл, первый ушёл |

## Что мы узнали?

- Стек — LIFO: push, pop, peek — O(1). Реализуется на slice или списке.
- Очередь — FIFO: enqueue, dequeue — O(1). Реализуется на списке или кольцевом буфере.
- Дек — двусторонняя: все операции O(1). Обобщение стека и очереди.
- Монотонный стек решает «следующий больший/меньший» за O(n).
- Монотонная очередь решает «максимум/минимум в скользящем окне» за O(n).
- Каждая структура — инструмент для конкретного класса задач.

---

## Типичные ошибки

- ❌ **Реализовывать очередь на slice через `items[1:]`.** Сдвиг указателя — не копирование, но база растёт и память утекает.
- ❌ **Забывать проверять пустоту стека перед pop.** Паника при pop из пустого стека.
- ❌ **Путать монотонный стек и монотонную очередь.** Стек — LIFO, очередь — FIFO с окном.
- ❌ **Использовать монотонный стек там, где нужно окно.** Монотонный стек не удаляет элементы по времени — только по значению.
- ❌ **Думать, что вложенные циклы в монотонном стеке дают O(n²).** Каждый элемент push/pop один раз — O(n).

---

## Для быстрого повторения

- **Стек:** LIFO. Реализация: slice (`append`, `[:len-1]`) или список (head). Применение: скобки, undo, call stack, DFS.
- **Очередь:** FIFO. Реализация: список (head+tail) или кольцевой буфер. Применение: BFS, буферы, планировщики.
- **Дек:** оба конца. Реализация: двусвязный список или кольцевой буфер. Применение: скользящее окно, история.
- **Монотонный стек:** убывающий → следующий больший. Возрастающий → следующий меньший. O(n).
- **Монотонная очередь:** дек + FIFO. Максимум/минимум в окне. O(n).
- **Паттерн:** каждый элемент push/pop один раз → O(n), несмотря на вложенные циклы.

## Ответы

**1.** Стек — структура LIFO. Операции: push (добавить на вершину) — O(1), pop (извлечь вершину) — O(1), peek (посмотреть вершину) — O(1), isEmpty — O(1). Реализуется на slice или связном списке.

**2.** Очередь — структура FIFO. Отличие от стека: порядок извлечения. Стек — последний добавленный извлекается первым. Очередь — первый добавленный извлекается первым.

**3.** На slice напрямую нельзя: `items[1:]` не копирует данные, но база растёт, а начало «съедается» — утечка памяти. Альтернативы: связный список (head + tail, O(1) на все операции) или кольцевой буфер (фиксированная ёмкость, индексы по модулю).

**4.** Дек — двусторонняя очередь: добавление и извлечение с обоих концов. Стек — дек, где доступен только один конец (pushBack + popBack). Очередь — дек, где добавление только в конец, извлечение только из начала.

**5.** Монотонный стек поддерживает элементы в возрастающем или убывающем порядке. При добавлении выталкивает всё, что нарушает порядок. Решает задачу «следующий больший/меньший элемент»: когда элемент x выталкивает y, это значит, что x — следующий больший для y.

**6.** Монотонная очередь — это дек с монотонным порядком + FIFO. Отличие от монотонного стека: в очереди есть **окно** — элементы удаляются не только по значению, но и по времени (когда выходят за пределы окна). Решает задачу «максимум/минимум в скользящем окне».

**7.** Потому что каждый элемент кладётся в стек **один раз** и выталкивается **один раз**. Суммарное количество операций push + pop = 2n = O(n). Вложенные циклы не означают O(n²), если внутренний цикл суммарно выполняется O(n) раз.

**8.** Два стека: `in` (для enqueue) и `out` (для dequeue). Enqueue: push в `in` — O(1). Dequeue: если `out` пуст — перекладываем все элементы из `in` в `out` (порядок разворачивается), потом pop из `out`. Амортизированное O(1): каждый элемент перекладывается не более одного раза.

**9.** Идём по токенам. Число — push в стек. Оператор — pop два числа, вычисляем, push результат. В конце в стеке одно число — ответ.

**10.** Стек: call stack (вызовы функций), undo/redo (история действий), парсинг выражений (скобки, RPN), DFS (обход графа). Очередь: BFS (обход графа в ширину), буферы сообщений (Kafka), планировщики задач (очередь готовых процессов), каналы в Go.
