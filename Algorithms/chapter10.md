## 10.0 Пролог: топ-10 из миллиарда записей

Вернёмся к прологу Главы 5. Сервис аналитики получает CSV с транзакциями. Нужно показать топ-10 крупнейших по сумме.

Данных много — миллиард транзакций. Сортировать всё — O(n log n) = 30 миллиардов операций. Секунды, минуты. Неприемлемо.

**Ключевое наблюдение:** нам нужны только **10 элементов**. Мы сортируем миллиард ради десяти. Это как сортировать всю библиотеку, чтобы найти десять самых толстых книг.

**Идея:** поддерживаем **только 10 элементов** — самых крупных на данный момент. При чтении новой транзакции:

- Если она меньше минимальной из топ-10 — пропускаем.
- Если больше — заменяем минимальную и восстанавливаем порядок.

Для этого нужна структура, которая **мгновенно даёт минимум** и **быстро обновляется**. Это **куча** (heap) — или, точнее, **min-heap**.

**Сложность:** O(n · log k), где k = 10. Для миллиарда и k=10 — 30 миллиардов × log(10) ≈ 100 миллиардов. Но каждая операция — O(1) в среднем (потому что большинство элементов меньше минимума и пропускаются).

**Реальная сложность:** O(n + n·log k) в худшем, но на практике почти O(n). Потому что большинство элементов не попадают в топ.

В этой главе мы разберём **кучи** — структуру, которая лежит в основе приоритетных очередей, top-K, планировщиков, алгоритмов на графах (Дейкстра, A*).

## 10.1 Что такое куча и зачем она нужна

### 🔌 Проблема: как мгновенно получать максимум или минимум?

У тебя есть набор чисел. Ты хочешь:

1. **Мгновенно** получать максимальный элемент.
2. **Быстро** вставлять новый элемент.
3. **Быстро** удалять максимальный.

**Массив:** поиск максимума — O(n). Вставка — O(1). Удаление максимума — O(n) (нужно найти и удалить).

**Отсортированный массив:** максимум — O(1). Вставка — O(n) (нужно вставить в правильное место). Удаление — O(n).

**BST:** всё — O(log n). Но BST требует памяти на указатели и балансировки.

**Нужна структура, которая:**

- Даёт максимум/минимум за O(1).
- Вставку и удаление — за O(log n).
- Использует O(n) памяти без указателей.

Эта структура — **куча**.

### 📐 Что такое куча

**Куча (heap)** — это **полное бинарное дерево**, где выполняется свойство кучи:

> Для **max-heap**: каждый узел **≥** своих потомков. Корень — максимум.
>
> Для **min-heap**: каждый узел **≤** своих потомков. Корень — минимум.

**Пример max-heap:**

```
        9
       / \
      7   8
     / \ /
    5  6 4
```

**Пример min-heap:**

```
        1
       / \
      3   2
     / \ /
    5  7 6
```

**Полное бинарное дерево** — все уровни заполнены, кроме, возможно, последнего. Последний уровень заполнен **слева направо**.

### 📐 Куча как массив

**Ключевое преимущество кучи:** её можно хранить в **массиве** без указателей.

Для узла с индексом `i`:

- Левый потомок: `2i + 1`.
- Правый потомок: `2i + 2`.
- Родитель: `(i - 1) / 2`.

**Пример max-heap в массиве:**

```
Дерево:
        9
       / \
      7   8
     / \ /
    5  6 4

Массив: [9, 7, 8, 5, 6, 4]
Индексы: 0  1  2  3  4  5

Проверка:
- arr[0] = 9, потомки arr[1] = 7, arr[2] = 8. 9 ≥ 7, 9 ≥ 8. ✅
- arr[1] = 7, потомки arr[3] = 5, arr[4] = 6. 7 ≥ 5, 7 ≥ 6. ✅
- arr[2] = 8, потомок arr[5] = 4. 8 ≥ 4. ✅
```

**Преимущества:**

1. **O(1) на доступ к корню** — `arr[0]`.
2. **Нет указателей** — экономия памяти.
3. **Кэш-локальность** — данные лежат подряд (подглава 2.2).

### 📊 Операции кучи

| Операция | Сложность |
|:---|:---|
| `peek()` — посмотреть максимум/минимум | O(1) |
| `push(x)` — вставить элемент | O(log n) |
| `pop()` — извлечь максимум/минимум | O(log n) |
| `build(arr)` — построить кучу из массива | O(n) |
| `heapify(i)` — восстановить свойство кучи | O(log n) |

### 💡 Что мы узнали?

- Куча — полное бинарное дерево со свойством: родитель ≥ (или ≤) потомков.
- Хранится в массиве: потомки узла `i` — `2i+1` и `2i+2`.
- Корень — максимум (max-heap) или минимум (min-heap).
- Peek — O(1), push/pop — O(log n), build — O(n).
- Нет указателей, хорошая кэш-локальность.

## 10.2 Sift up и sift down: как поддерживать кучу

### 🔌 Проблема: как восстановить свойство кучи после вставки/удаления?

Вставка элемента может нарушить свойство кучи. Например, вставляем 10 в max-heap:

```
        9
       / \
      7   8
     / \ /
    5  6 4

Вставляем 10 в конец: [9, 7, 8, 5, 6, 4, 10]

Дерево:
        9
       / \
      7   8
     / \ / \
    5  6 4 10

Свойство нарушено: 8 < 10, 9 < 10.
```

Нужно **восстановить** свойство. Для этого есть две операции: **sift up** и **sift down**.

### 📐 Sift up (просеивание вверх)

**Когда:** после вставки нового элемента в конец.

**Идея:** новый элемент «всплывает» вверх, пока не займёт правильное место.

**Алгоритм:**

1. Ставим элемент в конец массива.
2. Сравниваем его с родителем.
3. Если элемент больше родителя (для max-heap) — меняем местами.
4. Повторяем, пока элемент не станет ≤ родителя или не дойдёт до корня.

**Пример:** вставляем 10 в max-heap `[9, 7, 8, 5, 6, 4]`.

```
Шаг 1: добавляем 10 в конец. Массив: [9, 7, 8, 5, 6, 4, 10]
       Индекс 10: 6. Родитель: (6-1)/2 = 2 (значение 8).
       10 > 8 → меняем.

Шаг 2: массив: [9, 7, 10, 5, 6, 4, 8]
       Индекс 10: 2. Родитель: (2-1)/2 = 0 (значение 9).
       10 > 9 → меняем.

Шаг 3: массив: [10, 7, 9, 5, 6, 4, 8]
       Индекс 10: 0 — корень. Останавливаемся.

Готово: [10, 7, 9, 5, 6, 4, 8]
```

**Код:**

```go
func siftUp(heap []int, i int) {
    for i > 0 {
        parent := (i - 1) / 2
        if heap[i] <= heap[parent] {
            break
        }
        heap[i], heap[parent] = heap[parent], heap[i]
        i = parent
    }
}
```

**Сложность:** O(log n) — высота дерева.

### 📐 Sift down (просеивание вниз)

**Когда:** после удаления корня (или при построении кучи).

**Идея:** элемент «погружается» вниз, пока не займёт правильное место.

**Алгоритм:**

1. Меняем корень с последним элементом.
2. Удаляем последний (старый корень).
3. Новый корень сравниваем с потомками.
4. Меняем с **большим** из потомков (для max-heap).
5. Повторяем, пока элемент не станет ≥ обоих потомков или не дойдёт до листа.

**Пример:** удаляем корень 10 из `[10, 7, 9, 5, 6, 4, 8]`.

```
Шаг 1: меняем корень с последним. [8, 7, 9, 5, 6, 4, 10]
       Удаляем последний. Массив: [8, 7, 9, 5, 6, 4]

Шаг 2: sift down с индекса 0 (значение 8).
       Потомки: 7 (индекс 1), 9 (индекс 2). Больший — 9.
       8 < 9 → меняем с 9.

Шаг 3: массив: [9, 7, 8, 5, 6, 4]
       Индекс 8: 2. Потомки: 4 (индекс 5). 8 > 4 → останавливаемся.

Готово: [9, 7, 8, 5, 6, 4]
```

**Код:**

```go
func siftDown(heap []int, i, n int) {
    for {
        left := 2*i + 1
        right := 2*i + 2
        largest := i
        
        if left < n && heap[left] > heap[largest] {
            largest = left
        }
        if right < n && heap[right] > heap[largest] {
            largest = right
        }
        
        if largest == i {
            break
        }
        
        heap[i], heap[largest] = heap[largest], heap[i]
        i = largest
    }
}
```

**Сложность:** O(log n).

### 🧮 Почему O(log n)

Sift up и sift down проходят от корня до листа или наоборот. Высота полного бинарного дерева с n узлами — O(log n). Значит, O(log n) шагов.

### 💡 Что мы узнали?

- Sift up: новый элемент «всплывает» вверх. O(log n).
- Sift down: элемент «погружается» вниз. O(log n).
- Sift up используется при вставке, sift down — при удалении корня.
- Обе операции — O(log n) по высоте дерева.

## 10.3 Построение кучи за O(n)

### 🔌 Проблема: как построить кучу из массива?

Дан массив чисел. Нужно превратить его в кучу.

**Наивный подход:** вставлять элементы по одному через sift up. Каждая вставка — O(log n). Итого O(n log n).

**Вопрос:** можно ли быстрее?

Да, за **O(n)**.

### 📐 Идея: sift down с середины

**Ключевое наблюдение:** листья уже являются кучами (у них нет потомков). Значит, их не нужно трогать.

Начинаем с **последнего нелистового узла** — `n/2 - 1` — и идём вверх до корня, вызывая **sift down** для каждого узла.

**Алгоритм:**

1. Для `i` от `n/2 - 1` до 0:
   - Вызываем `siftDown(heap, i, n)`.
2. Готово — массив стал кучей.

### 🔬 Пример

**Массив:** `[4, 10, 3, 5, 1, 8]`

```
Начальное дерево:
        4
       / \
      10  3
     / \ /
    5  1 8

Листья: 5, 1, 8 — уже кучи. Начинаем с индекса n/2 - 1 = 2 (значение 3).

Шаг 1: sift down с индекса 2 (значение 3).
  Потомки: 8 (индекс 5). 3 < 8 → меняем.
  Массив: [4, 10, 8, 5, 1, 3]

Шаг 2: sift down с индекса 1 (значение 10).
  Потомки: 5 (индекс 3), 1 (индекс 4). Больший — 5.
  10 > 5 → останавливаемся.
  Массив: [4, 10, 8, 5, 1, 3]

Шаг 3: sift down с индекса 0 (значение 4).
  Потомки: 10 (индекс 1), 8 (индекс 2). Больший — 10.
  4 < 10 → меняем.
  Массив: [10, 4, 8, 5, 1, 3]
  Индекс 4: 1. Потомки: 5 (индекс 3), 1 (индекс 4). Больший — 5.
  4 < 5 → меняем.
  Массив: [10, 5, 8, 4, 1, 3]

Готово: [10, 5, 8, 4, 1, 3] — куча.
```

### 🧮 Почему O(n), а не O(n log n)

**Наивный анализ:** n/2 узлов, каждый sift down — O(log n). Итого O(n log n).

**Точный анализ:** sift down для узла на высоте h стоит O(h). Узлов на высоте h — около n/2^(h+1). Суммарная стоимость:

```
T(n) = Σ (n/2^(h+1)) · h, для h от 0 до log n
     = (n/2) · Σ h/2^h
     = (n/2) · 2 (сумма ряда Σ h/2^h = 2)
     = n
```

**Итого: O(n).**

**Интуиция:** большинство узлов находятся близко к листьям (высота 1–2), и sift down для них дешёвый. Только корень требует O(log n), но он один.

### 🔬 Код

```go
func buildHeap(arr []int) {
    n := len(arr)
    for i := n/2 - 1; i >= 0; i-- {
        siftDown(arr, i, n)
    }
}
```

### 📊 Сравнение

| Метод | Сложность |
|:---|:---|
| По одному через sift up | O(n log n) |
| Sift down с середины | **O(n)** |

**O(n) построение** используется в heap sort и в приоритетных очередях.

### 💡 Что мы узнали?

- Построение кучи за O(n): sift down с середины массива.
- Листья уже кучи — начинаем с последнего нелистового узла.
- Точный анализ: сумма по высотам даёт O(n).
- Это быстрее, чем вставка по одному (O(n log n)).

## 10.4 Heap sort: сортировка на месте

### 🔌 Проблема: как отсортировать массив, используя кучу?

У нас есть куча. Мы знаем, что корень — максимум. Как отсортировать массив?

**Идея:**

1. Построить max-heap из массива (O(n)).
2. Извлекать максимум из кучи n раз.
3. Каждый раз ставить максимум в конец массива.

**Результат:** массив отсортирован по возрастанию.

### 📐 Алгоритм

1. **Построить max-heap** из массива.
2. Для `i` от `n-1` до 1:
   - Меняем `arr[0]` (корень, максимум) с `arr[i]`.
   - Уменьшаем размер кучи на 1 (`n = i`).
   - Вызываем `siftDown(arr, 0, i)` — восстанавливаем кучу в оставшейся части.

**Почему это работает:** на каждом шаге мы извлекаем максимум (корень) и ставим его в конец **отсортированной части**. Размер кучи уменьшается — мы больше не трогаем отсортированный хвост.

### 🔬 Пример

**Массив:** `[4, 10, 3, 5, 1, 8]`

**Шаг 1: построить max-heap.**

```
После buildHeap: [10, 5, 8, 4, 1, 3]

Дерево:
        10
       /  \
      5    8
     / \  /
    4  1 3
```

**Шаг 2: извлечение максимума.**

```
i=5: меняем arr[0]=10 и arr[5]=3. Массив: [3, 5, 8, 4, 1, 10]
     sift down на [3, 5, 8, 4, 1]: [8, 5, 3, 4, 1, 10]

i=4: меняем arr[0]=8 и arr[4]=1. Массив: [1, 5, 3, 4, 8, 10]
     sift down на [1, 5, 3, 4]: [5, 4, 3, 1, 8, 10]

i=3: меняем arr[0]=5 и arr[3]=1. Массив: [1, 4, 3, 5, 8, 10]
     sift down на [1, 4, 3]: [4, 1, 3, 5, 8, 10]

i=2: меняем arr[0]=4 и arr[2]=3. Массив: [3, 1, 4, 5, 8, 10]
     sift down на [3, 1]: [3, 1, 4, 5, 8, 10]

i=1: меняем arr[0]=3 и arr[1]=1. Массив: [1, 3, 4, 5, 8, 10]

Готово: [1, 3, 4, 5, 8, 10]
```

### 🔬 Код

```go
func heapSort(arr []int) {
    n := len(arr)
    
    // 1. Построить max-heap
    for i := n/2 - 1; i >= 0; i-- {
        siftDown(arr, i, n)
    }
    
    // 2. Извлекать максимум и ставить в конец
    for i := n - 1; i > 0; i-- {
        arr[0], arr[i] = arr[i], arr[0]
        siftDown(arr, 0, i)
    }
}
```

### 🧮 Сложность

**Время:**

- Построение кучи: O(n).
- n извлечений, каждое O(log n): O(n log n).
- **Итого:** O(n log n) в **любом** случае.

**Память:** O(1) — сортировка на месте.

**Стабильность:** ❌ нестабильна.

### 📊 Сравнение с другими сортировками

| | Heap sort | Merge sort | Quicksort |
|:---|:---|:---|:---|
| Среднее | O(n log n) | O(n log n) | O(n log n) |
| Худшее | O(n log n) | O(n log n) | O(n²) |
| Память | O(1) | O(n) | O(log n) |
| Стабильность | ❌ | ✅ | ❌ |
| Кэш-локальность | Плохая | Хорошая | Отличная |

**Почему heap sort не используется на практике:**

- **Плохая кэш-локальность.** Sift down прыгает по массиву: `2i+1`, `2i+2`, затем `2(2i+1)+1`, ... Это не последовательный доступ.
- **Quicksort быстрее** на практике из-за лучшей кэш-локальности.
- **Heap sort используется в pdqsort как fallback** — когда quicksort деградирует до O(n²), переключаются на heap sort (подглава 5.7).

### 💡 Что мы узнали?

- Heap sort: построить max-heap, извлекать максимум, ставить в конец.
- O(n log n) в любом случае, O(1) памяти, нестабильна.
- Плохая кэш-локальность — поэтому редко используется напрямую.
- Используется как fallback в гибридных сортировках (pdqsort).

## 10.5 Приоритетная очередь: применение кучи

### 🔌 Проблема: как обрабатывать задачи с приоритетами?

В реальных системах задачи имеют разные приоритеты:

- Планировщик ОС: процессы с высоким приоритетом выполняются первыми.
- Обработчик событий: события с высоким приоритетом обрабатываются раньше.
- Маршрутизатор: пакеты с высоким приоритетом отправляются первыми.

Для этого нужна **приоритетная очередь** — структура, где элементы извлекаются в порядке приоритета, а не в порядке добавления.

**Приоритетная очередь** реализуется через **кучу**.

### 📐 Операции приоритетной очереди

| Операция | Сложность |
|:---|:---|
| `Push(x, priority)` | O(log n) |
| `Pop()` — извлечь элемент с наивысшим приоритетом | O(log n) |
| `Peek()` — посмотреть элемент с наивысшим приоритетом | O(1) |
| `Size()` | O(1) |
| `IsEmpty()` | O(1) |

**Max-priority queue:** извлекается элемент с **наибольшим** приоритетом (max-heap).

**Min-priority queue:** извлекается элемент с **наименьшим** приоритетом (min-heap).

### 🔬 Применения

**1. Планировщик задач.** Задачи с высоким приоритетом выполняются первыми.

**2. Алгоритм Дейкстры.** На каждом шаге извлекается вершина с минимальным расстоянием. Разберём в Главе 14.

**3. Алгоритм A\*.** Поиск кратчайшего пути с эвристикой. Приоритет — оценка расстояния.

**4. Merge k sorted lists.** На каждом шаге извлекается минимальный элемент среди голов k списков. Разберём в практике.

**5. Медиана в потоке.** Поддерживаем две кучи: max-heap для левой половины, min-heap для правой. Медиана — на границе.

**6. Топ-K.** Поддерживаем min-heap размера k. Новый элемент заменяет минимум, если он больше.

**7. Кодирование Хаффмана.** На каждом шаге объединяются два узла с наименьшей частотой.

### 💡 Что мы узнали?

- Приоритетная очередь — структура, где элементы извлекаются по приоритету.
- Реализуется через кучу.
- Применения: планировщики, Дейкстра, A*, merge k lists, топ-K, медиана в потоке.

## 10.6 container/heap в Go

### 🔌 Проблема: писать кучу каждый раз?

Go предоставляет `container/heap` — обобщённую реализацию кучи. Но она требует реализации интерфейса `heap.Interface`.

### 📐 Интерфейс heap.Interface

```go
type Interface interface {
    sort.Interface
    Push(x any)  // добавить элемент
    Pop() any    // извлечь элемент с наивысшим приоритетом
}

type sort.Interface interface {
    Len() int
    Less(i, j int) bool
    Swap(i, j int)
}
```

**Что нужно реализовать:**

- `Len() int` — количество элементов.
- `Less(i, j int) bool` — компаратор (для min-heap: `heap[i] < heap[j]`).
- `Swap(i, j int)` — обмен элементов.
- `Push(x any)` — добавление в конец (вызывается из `heap.Push`).
- `Pop() any` — удаление последнего (вызывается из `heap.Pop`).

**Стандартные функции:**

- `heap.Init(h)` — построить кучу из массива.
- `heap.Push(h, x)` — вставить элемент.
- `heap.Pop(h)` — извлечь элемент с наивысшим приоритетом.
- `heap.Fix(h, i)` — восстановить кучу после изменения приоритета элемента `i`.
- `heap.Remove(h, i)` — удалить элемент по индексу.

### 🔬 Пример: min-heap

```go
type IntHeap []int

func (h IntHeap) Len() int           { return len(h) }
func (h IntHeap) Less(i, j int) bool { return h[i] < h[j] }
func (h IntHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }

func (h *IntHeap) Push(x any) {
    *h = append(*h, x.(int))
}

func (h *IntHeap) Pop() any {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func main() {
    h := &IntHeap{5, 2, 8, 1, 9}
    heap.Init(h)
    
    fmt.Println("Min:", (*h)[0]) // 1
    
    heap.Push(h, 3)
    fmt.Println("Min after push 3:", (*h)[0]) // 1
    
    min := heap.Pop(h)
    fmt.Println("Popped:", min) // 1
    fmt.Println("Min after pop:", (*h)[0]) // 2
}
```

### 🔬 Пример: max-heap

Для max-heap просто меняем компаратор на `>`:

```go
func (h IntHeap) Less(i, j int) bool { return h[i] > h[j] }
```

И `heap.Init`, `heap.Push`, `heap.Pop` работают корректно.

### 📊 Пример: приоритетная очередь с кастомными элементами

```go
type Task struct {
    ID       int
    Priority int
}

type TaskHeap []Task

func (h TaskHeap) Len() int           { return len(h) }
func (h TaskHeap) Less(i, j int) bool { return h[i].Priority > h[j].Priority } // max-heap
func (h TaskHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }

func (h *TaskHeap) Push(x any) {
    *h = append(*h, x.(Task))
}

func (h *TaskHeap) Pop() any {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func main() {
    h := &TaskHeap{
        {1, 5},
        {2, 10},
        {3, 3},
    }
    heap.Init(h)
    
    top := heap.Pop(h)
    fmt.Println("Top priority:", top) // {2 10}
}
```

### 📊 Пример: изменение приоритета

`heap.Fix(h, i)` — восстановить кучу после изменения элемента `i`. Это важно для алгоритмов типа Дейкстры, где нужно уменьшить расстояние до вершины.

```go
// Уменьшили приоритет элемента с индексом 2
(*h)[2].Priority = 1
heap.Fix(h, 2)
```

### 💡 Что мы узнали?

- `container/heap` — обобщённая реализация.
- Реализуем `Len`, `Less`, `Swap`, `Push`, `Pop`.
- `Less` определяет порядок: `<` для min-heap, `>` для max-heap.
- `heap.Init`, `heap.Push`, `heap.Pop`, `heap.Fix`, `heap.Remove`.
- Кастомные структуры — через реализацию интерфейса.

## 10.7 Практика: решаем задачи

### 📝 Задача 1: K-th Largest Element in Array

**Формулировка:** дан массив чисел и k. Найти k-й наибольший элемент.

**Пример:**

```
Вход: nums = [3, 2, 1, 5, 6, 4], k = 2
Выход: 5
```

**Подход 1: сортировка**

O(n log n). Мы разбирали в Главе 5.

**Подход 2: min-heap размера k**

Поддерживаем min-heap из k элементов — **k наибольших на текущий момент**. Корень — **k-й наибольший**.

```go
func findKthLargest(nums []int, k int) int {
    h := &IntHeap{} // min-heap
    heap.Init(h)
    
    for _, x := range nums {
        heap.Push(h, x)
        if h.Len() > k {
            heap.Pop(h)
        }
    }
    
    return heap.Pop(h)
}
```

**Сложность:** O(n log k).

**Почему работает:** min-heap размера k всегда содержит k **наибольших** элементов. Корень — минимум среди них, то есть k-й наибольший.

### 📝 Задача 2: Merge k Sorted Lists

**Формулировка:** даны k отсортированных связных списков. Слить в один отсортированный.

**Пример:**

```
Вход: [[1→4→5], [1→3→4], [2→6]]
Выход: [1→1→2→3→4→4→5→6]
```

**Подход:** min-heap из голов всех списков.

```go
func mergeKLists(lists []*Node) *Node {
    h := &ListHeap{}
    heap.Init(h)
    
    for _, list := range lists {
        if list != nil {
            heap.Push(h, list)
        }
    }
    
    dummy := &Node{}
    cur := dummy
    
    for h.Len() > 0 {
        node := heap.Pop(h).(*Node)
        cur.Next = node
        cur = node
        
        if node.Next != nil {
            heap.Push(h, node.Next)
        }
    }
    
    return dummy.Next
}
```

**Сложность:** O(N log k), где N — общее количество узлов.

### 📝 Задача 3: Top-K Frequent Elements

**Формулировка:** дан массив чисел и k. Найти k самых часто встречающихся.

**Пример:**

```
Вход: nums = [1, 1, 1, 2, 2, 3], k = 2
Выход: [1, 2]
```

**Подход 1: подсчёт + сортировка**

O(n + m log m), где m — количество уникальных.

**Подход 2: подсчёт + min-heap размера k**

```go
func topKFrequent(nums []int, k int) []int {
    counts := make(map[int]int)
    for _, x := range nums {
        counts[x]++
    }
    
    h := &FreqHeap{}
    heap.Init(h)
    
    for num, count := range counts {
        heap.Push(h, Freq{num, count})
        if h.Len() > k {
            heap.Pop(h)
        }
    }
    
    result := make([]int, 0, k)
    for h.Len() > 0 {
        result = append(result, heap.Pop(h).(Freq).num)
    }
    return result
}
```

**Сложность:** O(n + m log k). Быстрее сортировки, если m >> k.

### 📝 Задача 4: Find Median from Data Stream

**Формулировка:** дан поток чисел. После каждого добавления найди медиану.

**Пример:**

```
addNum(1) → медиана 1
addNum(2) → медиана 1.5
addNum(3) → медиана 2
```

**Подход:** две кучи.

- **Max-heap** для **меньшей половины**.
- **Min-heap** для **большей половины**.

Поддерживаем размеры так, чтобы:

- `maxHeap.Len() == minHeap.Len()` или `maxHeap.Len() == minHeap.Len() + 1`.
- Все элементы в max-heap ≤ всех элементов в min-heap.

```go
type MedianFinder struct {
    maxHeap *IntHeap // меньшая половина
    minHeap *IntHeap // большая половина
}

func (mf *MedianFinder) AddNum(num int) {
    heap.Push(mf.maxHeap, num)
    heap.Push(mf.minHeap, heap.Pop(mf.maxHeap))
    
    // Балансируем размеры
    if mf.maxHeap.Len() < mf.minHeap.Len() {
        heap.Push(mf.maxHeap, heap.Pop(mf.minHeap))
    }
}

func (mf *MedianFinder) FindMedian() float64 {
    if mf.maxHeap.Len() > mf.minHeap.Len() {
        return float64(heap.Pop(mf.maxHeap))
    }
    return float64(heap.Pop(mf.maxHeap)+heap.Pop(mf.minHeap)) / 2
}
```

**Сложность:** O(log n) на добавление, O(1) на медиану.

**Ключевая идея:** медиана — граница между двумя половинами. Max-heap даёт максимум левой половины, min-heap — минимум правой.

### 💡 Что мы узнали?

- **K-th Largest:** min-heap размера k. O(n log k).
- **Merge k Lists:** min-heap из голов. O(N log k).
- **Top-K Frequent:** подсчёт + min-heap. O(n + m log k).
- **Median in Stream:** две кучи. O(log n) на добавление.
- Все задачи используют **кучу для поддержания топ-K или медианы**.

## Типичные ошибки

- ❌ **Использовать max-heap для top-K наибольших.** Нужен **min-heap** размера k.
- ❌ **Строить кучу через n вставок.** Это O(n log n). Используй sift down с середины — O(n).
- ❌ **Забывать про индексацию в Go.** Потомки узла `i` — `2i+1` и `2i+2`, родитель — `(i-1)/2`.
- ❌ **Использовать heap sort вместо quicksort.** Heap sort медленнее из-за плохой кэш-локальности.
- ❌ **Забывать про `heap.Fix` после изменения приоритета.** Иначе куча не перестроится.
- ❌ **Путать max-heap и min-heap в `container/heap`.** `Less` определяет порядок: `<` для min, `>` для max.

- **Куча:** полное бинарное дерево. Max-heap: родитель ≥ потомков. Min-heap: родитель ≤ потомков.

---

## Ответы

**1.** Куча — полное бинарное дерево с свойством: для max-heap каждый узел ≥ своих потомков (корень — максимум); для min-heap каждый узел ≤ своих потомков (корень — минимум).

**2.** Куча хранится в массиве. Для узла `i`: левый потомок — `2i+1`, правый — `2i+2`, родитель — `(i-1)/2`. Это работает, потому что дерево полное.

**3.** **Sift up** — просеивание нового элемента вверх при вставке (сравнение с родителем). **Sift down** — просеивание элемента вниз при удалении корня или построении кучи (сравнение с потомками).

**4.** Sift down для узла на высоте h стоит O(h). Узлов на высоте h — около n/2^(h+1). Суммарная стоимость — Σ (n/2^(h+1)) · h = O(n). Большинство узлов близко к листьям, где h мало.

**5.** Heap sort: (1) построить max-heap за O(n); (2) n раз извлечь максимум (каждое O(log n)) и поставить в конец. Итого O(n + n log n) = O(n log n). В любом случае, потому что не зависит от данных.

**6.** Плохая кэш-локальность. Sift down прыгает по массиву (`2i+1`, `2i+2`, затем `2(2i+1)+1`, ...), а не идёт последовательно. Quicksort быстрее из-за лучшей кэш-локальности.

**7.** Приоритетная очередь — структура, где элементы извлекаются по приоритету (не по порядку добавления). Реализуется через кучу: `push` — O(log n), `pop` — O(log n), `peek` — O(1).

**8.** Для k-го наибольшего нужен **min-heap** размера k. Он хранит k наибольших элементов. Корень — минимум среди них, то есть k-й наибольший. Max-heap размера k дал бы k наименьших.

**9.** Две кучи: **max-heap** для меньшей половины, **min-heap** для большей. Поддерживаем размеры равными (или max-heap на 1 больше). Медиана — корень max-heap (если нечётное) или среднее корней (если чётное).

**10.** Реализовать `Len`, `Less`, `Swap`, `Push`, `Pop`. `Less(i, j)` — компаратор: `<` для min-heap, `>` для max-heap. `Push` и `Pop` добавляют/удаляют элементы в конец. `heap.Init`, `heap.Push`, `heap.Pop` используют эти методы.
